# ADR-010：WHERE 合取项拆分与分别下推

状态：已实现（Accepted）
日期：2026-11-20

## 背景

ADR-009 只把**整条** `WHERE` 谓词下推到扫描，因此 `WHERE a.id = 2 AND b.w = 'b2'` 这种常见的多源合取仍然整体留在 join 后：两张源表都没有提前过滤，join 的输入行数也没有减少。把顶层 `AND` 拆开、按来源分别下推，可以直接覆盖这类查询，而不需要引入索引或全局计划搜索。

## 决策

1. 只拆分 `WHERE` 顶层（含括号嵌套）的 `AND` 合取项；`OR` 分支、`NOT` 内部以及 `CASE` 中的 `AND` 都不拆。只对全部由 `INNER` / `CROSS` join 组成的链拆分，外连接仍整体留在 join 后。
2. 每个合取项独立判断是否可下推：
   - 所有列都必须显式限定（`alias.column` / `table.column`）；
   - 只引用一个源表；
   - 该 qualifier 必须能在 base-table + join 书写顺序中找到。
   不满足任一条件的合取项进入残余 `WHERE`，不因同一 `WHERE` 里其他合取项可下推而改变。
3. 同一源表的多个可下推合取项按原顺序用 `AND` 组合，作为该源表的一次扫描过滤；`PushdownPlan` 从“单个 source/filter”改为“每个源表一个可选组合谓词 + 残余谓词”。
4. 全部合取项都下推时，最终 `bind_select` 不再带 `WHERE`，计划中不生成 `Filter`；仍有残余时，残余合取项按原顺序用 `AND` 重组，继续显示为 join 之上的 `Filter`。
5. `EXPLAIN SELECT` / `EXPLAIN ANALYZE` 的 `Scan ... filtered` 标记和 `scan_filters` 仍然按源表布尔值记录；同一源表的多个合取项共享一个 `filtered` 标记。
6. 估算路径把每个源表组合后的谓词传给 `estimate_scan_rows`，沿用现有 `estimate_selectivity` 的 `AND` 相乘规则；过滤后的行数继续进入 join 基数、`Auto` 局部成本和后续节点估算。
7. 不拆分 `OR` 分支、不做外连接谓词下推、不解析未限定列、不做 join 重排、列裁剪、常量折叠或索引。

## 后果

- 正结果：`WHERE a.id = 2 AND b.w = 'b2'` 这类查询现在可以同时过滤两侧源表，join 输入行数和中间结果都会下降。
- 正结果：同一源表上的多个条件（如 `a.id = 2 AND a.v = 'a2'`）会合并成一次扫描过滤，不产生多个 `Filter` 节点。
- 正结果：不可下推的多源条件、`OR` 条件和外连接条件仍保留在 join 后，原有语义和计划观测方式不变。
- 负结果：谓词求值时机提前到源表扫描；对不产生运行时错误的谓词，结果行集不变，但错误/短路的触发顺序不再承诺与“先 join 再 WHERE”完全一致。
- 负结果：只拆顶层 `AND`；`WHERE (a.id = 2 OR b.id = 2) AND ...` 中的 `OR` 仍然整体不可下推。
- 负结果：外连接仍保守地整体跳过，即使其中某些合取项只引用被保留侧。
- 负结果：组合谓词会在该源表的每一行上求值；没有索引或跳过扫描，实际扫描量不减少。

## 被否掉的替代

- **继续只下推整条谓词**：实现简单，但会漏掉最常见的多源 `AND` 查询；ADR-009 已把这个限制记为后续切片。
- **把 `OR` 分支也拆开下推**：需要析取范式和跨来源的布尔推理，可能重复求值或改变三值逻辑的短路/错误行为，当前不做。
- **外连接也下推**：`LEFT JOIN` 右侧谓词下推会保留本应被 `WHERE` 丢弃的未匹配左行，需要 null-rejecting 分析或外连接降级；当前不做。
- **下推未限定列**：需要先在完整 schema 上解析归属，再映射回源表；当前 binder 的歧义规则可能因此改变。
- **直接引入逻辑计划/列裁剪/join 重排**：范围大于本切片；先把合取项拆分和残余条件闭合。
