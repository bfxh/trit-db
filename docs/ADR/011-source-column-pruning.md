# ADR-011：源表列裁剪

状态：已实现（Accepted）；后续 ADR-012 在计划入口做常量折叠与恒真条件简化，不改变本文的列需求收集和裁剪边界
日期：2026-11-20

## 背景

ADR-009 / ADR-010 已经把单源谓词和顶层 `AND` 合取项下推到源表扫描，join 的输入行数可以下降；但扫描、join 和中间表复制仍然携带源表的全部列。对于宽表，join 中间行的宽度和复制成本没有随查询实际需要的列收缩。当前执行路径先对完整 join 表逐行过滤，再排序，最后才在 projection 阶段求值输出列；因此中间阶段存在明显的无用列。

本切片只做一个保守的局部优化：在列引用可以完全静态归属到单个源表、且没有 `*` / `USING` / `NATURAL` 依赖时，提前把源表裁剪到查询真正需要的列。

## 决策

1. 在绑定之前收集查询所需列。收集范围包括：
   - `SELECT` 的每个表达式；
   - `WHERE` 原始谓词（包括已下推的合取项）；
   - `GROUP BY`、`HAVING`、`ORDER BY`；
   - 每个 `JOIN ... ON` 条件。
2. 只有所有列引用都带显式 qualifier（`alias.column` / `table.column`）时，才允许裁剪整条查询；出现未限定列时，整条查询退回完整 schema。这样不改变 binder 现有的后缀解析和歧义规则。
3. 出现 `SELECT *` 时整条查询退回完整 schema；`USING` / `NATURAL` join 也整条退回，因为合并列和别名解析依赖完整的 join schema。
4. 每个源表分别计算保留列：
   - 没有列被引用，或引用覆盖全部列时，不裁剪该源表；
   - 保留列是严格子集时，记录为 `Some(columns)`，按源表 schema 顺序保留。
5. 执行时在 `qualify_table` 的同一遍复制中完成裁剪（`qualify_table_projected`），避免先复制完整限定表再复制子集；源表文件仍然完整加载，裁剪只作用于 join 前的行副本和后续中间结果。
6. `ScanProjection` 与 `PushdownPlan` 分离：谓词下推决定扫描过滤，列裁剪决定扫描输出；两者可以同时生效，互不依赖。
7. `EXPLAIN SELECT` / `EXPLAIN ANALYZE` 在发生严格子集裁剪的 `Scan` 节点末尾追加 `cols=...`，列名按源表 schema 顺序、不带 qualifier。未裁剪的源表不追加该字段。
8. 不实现：表达式级投影下推、跨 join 的列需求传播、零列源表、索引覆盖、`SELECT *` 的按列裁剪、`USING` / `NATURAL` 的合并列裁剪、join 重排或逻辑计划。

## 后果

- 正结果：`SELECT a.v, b.w FROM a JOIN b ON a.id = b.id` 这类查询在 join 前只保留 `a.id,a.v` 和 `b.id,b.w`，未引用的宽列不再进入 join 中间行。
- 正结果：谓词下推和合取拆分仍可同时生效；`Scan ... filtered ... cols=...` 可以同时表达过滤和裁剪。
- 正结果：计划文本明确显示裁剪后的扫描列，`EXPLAIN` 和 `EXPLAIN ANALYZE` 都能观测到这一物理变化。
- 正结果：裁剪与统计、`Auto` join 成本选择解耦；行数和 NDV 仍来自完整表统计，不因裁剪改变 join 选择。
- 负结果：源表仍然完整加载到内存，扫描文件/页的 I/O 不减少；本切片减少的是 join 前副本宽度和中间结果宽度。
- 负结果：含未限定列、`SELECT *`、`USING` 或 `NATURAL` 的查询完全不裁剪，即使其中部分列确实未被使用。
- 负结果：不做表达式级需求分析；例如 `SELECT a.id + 1` 保留 `a.id`，但不会把表达式下推到扫描。
- 负结果：如果某源表在查询中没有被引用任何列（例如仅用于决定行多重性的 `CROSS JOIN`），仍保留全部列，而不是裁剪成零列或仅保留行计数。
- 负结果：计划中的 `cols=` 只是物理列清单，不承诺未来会改变 join 顺序或增加覆盖索引。

## 被否掉的替代

- **在所有查询上直接裁剪**：未限定列的归属由 binder 的后缀查找和歧义检测决定，提前裁剪会改变错误和歧义行为；当前先要求显式 qualifier。
- **裁剪 `SELECT *`**：需要把 `*` 展开成完整输出列并保留 `USING` / `NATURAL` 的合并列语义；范围大于本切片。
- **把列裁剪与谓词下推合并成一个计划结构**：两者输入条件不同，合并会让回退边界不清晰；当前保持 `PushdownPlan` 和 `ScanProjection` 独立。
- **在 `join_tables` 内部按需投影**：需要改动 join 布局和每一类 join 的输出映射，容易把外连接 NULL 填充和合并列语义弄错；当前在源表限定阶段一次完成。
- **引入完整逻辑计划和全局列需求传播**：范围大于本切片；先把单源、显式 qualifier 的物理裁剪闭合。
