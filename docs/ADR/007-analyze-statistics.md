# ADR-007：ANALYZE 统计与 EXPLAIN 估算

状态：已实现（Accepted）
日期：2026-11-20

## 背景

`EXPLAIN SELECT` 之前只输出静态计划节点，不显示任何基数信息；`EXPLAIN ANALYZE` 虽然执行一次并显示真实行数，但不能用于执行前的计划观察。表本身整表驻留内存，行数随时可读，但列级 NDV 需要扫描才能得到。

## 决策

1. 新增 `ANALYZE [table]`，精确扫描表并计算：
   - 行数；
   - 每列 `NULL` 数；
   - 每列非 `NULL` 不同值数（NDV）。
2. 统计以 `TRSS` v0 持久化在 `sql/stats/<table>`，重开后加载；解码时校验列名、行数和计数上界。
3. 表内容变化时，在重写表的同一事务里删除对应统计 key；`DROP TABLE` 同时删除表和统计。统计不会自动刷新，必须重新 `ANALYZE`。
4. `EXPLAIN SELECT` 在**所有源表都有统计**时追加 `est rows` / `est groups`；没有统计时保持原有不带数字的文本计划。估算只用简单启发式（等值 join 用两侧 NDV、过滤用选择率常量、分组用 NDV 乘积），不改变 `JoinStrategy`，也不执行查询。
5. `EXPLAIN ANALYZE` 只显示本次 `actual`，不混入统计估算。

## 后果

- 正结果：执行前可以看到基数估算；统计与表内容不会跨事务错配；重开后仍可用；没有引入额外后台任务。
- 负结果：写入后统计立即消失，必须手动 `ANALYZE`；没有直方图、采样、自动 analyze 或跨列相关性；估算可能偏离实际，尤其是 `IS NULL`、复杂谓词和外连接。
- 当前估算不参与 join 策略选择；`Auto` 仍按“有等值键就 hash”走，后续代价模型需要新增独立决策层。

## 被否掉的替代

- **每次 DML 自动重算统计**：与整表重写叠加，把每次写入变成额外全表扫描，M1 不接受。
- **只在内存缓存统计**：重开后 `EXPLAIN` 失去估算，且无法证明持久状态一致。
- **采样统计**：当前表规模小，精确扫描成本可控；采样会引入随机性和额外格式。
- **直接把统计喂给优化器**：当前没有逻辑计划/候选计划，先只做观测，避免把估算误称为代价模型。
