# 面向智能体的查询层：第一性原理与 trit-db 的落点

状态：方向文档（非承诺路线图）。日期：2026-11-21。

## 1. 观察：智能体与查询语言的错配

LLM 生成查询的基准里出现过一组很反直觉的数字：

- SQL：首轮正确率约 82%，但错误绝大多数是**静默错误**——查询跑通、结果错，智能体拿不到纠正信号；
- TypeQL：首轮 75%，其中 93% 的错误以数据库报错形式暴露，智能体重试 4 次后升到 92%，反超 SQL 的 83%。

把这些数字还原成第一性原理，结论只有一句：

> 对智能体而言，查询语言的价值 = 正确性保证 + **错误可判定性**（错误能否变成信号）。
> 语法熟悉度只影响首轮，错误信号决定收敛速度。

SQL 的静默错误有明确的来源，全是「合法的歧义」：

1. 三值逻辑里 `NULL` 同时表示「缺失」和「未知」，`NULL = NULL` 是 `UNKNOWN` 而不是 `TRUE`；
2. 隐式类型转换（`'1' = 1`、字符串比较的本地化）；
3. 聚合吞掉 `NULL`（`AVG` 的分母、`SUM` 全空返回 `NULL`）；
4. 空集语义（`NOT IN (空集)`、`EXISTS` 与 `COUNT(*)` 的空表分歧）；
5. 去重/排序的稳定性、`GROUP BY` 对 `NULL` 的分组。

这些在人类手里是「专业知识」，在智能体手里是「无声的坑」。

## 2. trit-db 已有的、别人没有的东西

翻一遍现有 crate，trit-db 恰好有三件与上述问题正相关、且别的 SQL 引擎没有的东西：

| 能力 | 位置 | 与「错误信号」的关系 |
|---|---|---|
| K3 / Belnap / Łukasiewicz / ℕ 四域注解 | `tritdb-exec::ann` | 冲突（`Both`）与未知（`Neither`）是一等值，不再被 `NULL` 吞掉 |
| `COUNT MODELS` / `UNDER REPAIR` | `tritdb-exec::ann`、SQL 层 | 答案本身带等级：`Certain` / `Contingent` / `Impossible` |
| 三值打包（1.6 bit/trit） | `tritdb-radix` | 位密度 ≈ 1.585 bit/trit，列存带宽天然低于布尔/字节 |

这三件事拼起来，正好是「可判定错误」的三个层次：
**值层**（注解不丢信息）→ **答案层**（结论带确定性）→ **存储层**（三值列存便宜）。

## 3. 三条设计原则（第一性原理推导）

### P1 显式不确定性，禁止静默降级

- 冲突数据用 `BOTH`、未知用 `NEITHER`/`NULL`，执行时不能隐式折叠成布尔；
- 查询结果附确定性等级：`CERTAIN`（所有修复/模型都成立）、`CONTINGENT`（部分成立）、
  `IMPOSSIBLE`（都不成立），`UNKNOWN` 只代表「值缺失」，不再代表「结论不确定」；
- 任何跨域运算（K3 × Ł × ℕ）必须报 `DomainMismatch`，不自动转换。

### P2 严格类型 + 结构化错误

- 混合类型比较报错（已是现状），不做隐式 cast；
- 错误要机器可读：错误码 + 期望/实际 + 修复建议（哪个列、哪个函数、合法值域），
  而不是一段自然语言。智能体的重试成本主要由「能不能读懂错误」决定。

### P3 三值列存：带宽是第一性约束

- 现代 CPU/GPU 的瓶颈是内存带宽而不是算力；三值打包 1.6 bit/trit 对布尔列是 5× 压缩、
  对 `i8` 是 5×、对 `i64` 是 40×；
- 因此「三值向量化」不需要 GPU 也能吃到收益：SIMD 一次处理 5 个 trit/字节；
- 这也是后续接 GPU 的接口形状——GPU 原生的优势同样来自带宽与并行，不是语言。

## 4. 对用户列的四个方向的取舍

| 方向 | 现象里的数字 | 本质 | trit-db 的取舍 |
|---|---|---|---|
| GPU 原生（星环） | TPC-DS 1TB 最高 66×、整体 456× | 带宽 + 并行 | 不追硬件；让**数据布局**（三值打包、列式）对 SIMD/GPU 友好，M10 做向量化执行 |
| 时序/列式（KDB-X） | 部分场景 1100×，4 线程 1.5% CPU | 列存 + 时间索引 + 向量化 | 已有 `timeidx`（ADR 034）；Q 三进制化是切入点，M8 先做 trit 向量内核 |
| NewSQL | 1000 节点 5–8× 吞吐 | 分布式架构 | 不追（单机 + CAS 复制已有），留到有明确需求 |
| 专用语言家族 | Flux / TDengine SQL / GQL / SPARQL / AQL / PRQL / Malloy / KQL / GraphQL | 语法不是壁垒，**数据模型 + 执行模型**才是 | 不发明语法；在 SQL 之上加「可判定的三值语义」，图/文档类交给 pgwire 生态 |

一句话：**不跟别人比语法和硬件，比「错误信号 + 三值数据模型 + 位压缩列存」。**

## 5. Q 的三进制化：设计

q/kdb+ 的内核只有四样东西：**列式向量**、**动词（verb）**、**副词（adverb）**、**表连接（asof）**。
三进制化不是把 q 的语法翻译一遍，而是把它的数据模型换成 trit：

### 5.1 数据模型

- `TritVec`：打包的 trit 向量（`r3`，5 trit/字节），语义由向量自身携带（K3 / Belnap / 平衡三进制数）；
- 平衡三进制整数 `TritInt`：`-1/0/+1`，权重 `3^k`，`i64` 可表示到 `3^40` 量级；
  对称、无符号位、乘法规则简单（`-1*1=-1`），适合做向量算术。

### 5.2 动词（M8 第一切片）

| 动词 | 语义 | 备注 |
|---|---|---|
| `neg` | K3 `¬`：F↔T，U 不变 | 逐元素 |
| `meet` | K3 `∧`：F 吸收 | 逐元素，映射到 q 的 `&` |
| `join` | K3 `∨`：T 吸收 | 逐元素，映射到 q 的 `|` |
| `add` | 平衡三进制加法 | `TritInt` 上实现，带进位 |
| `any` / `all` / `count_unknown` | 三值归约 | q 的 `|/`、`&/`、`sum` 的三值版本 |

### 5.3 副词与表（M9/M10）

- 副词（`each`、`over`、`scan`）先只做向量内归约与扫描；
- asof join（时序）与「三值缺失」天然契合：q 里的 `0N` 在 trit-db 里就是 `NEITHER`/`UNKNOWN`，
  不用额外的 null bitmap；
- 向量化执行：按 5 trit/字节的打包块做 SIMD 友好的逐块运算。

### 5.4 切片顺序

| 切片 | 内容 | 可判红 |
|---|---|---|
| M8（本刀） | `tritvec` 内核：`TritVec` + K3 动词/归约 + `TritInt` 平衡三进制加减 | 真值表、打包往返、归一化、溢出 |
| M9（已落地） | 查询级确定性等级：`certainty(expr)` 返回 `CERTAIN/CONTINGENT/IMPOSSIBLE`，普通查询也带答案等级 | 与 `UNDER REPAIR` 的答案对拍（同词汇、同枚举） |
| M10（批处理原语 + SELECT WHERE 已落地） | 三值批量谓词 + asof join（`tritdb-exec::batch`），SELECT 的纯注解列 WHERE 已切批量路径；ASOF JOIN 语法与三值列存块待做 | 谓词对标量真值表对拍、asof 对暴力对拍、WHERE 在 debug 构建与行式路径逐查询对拍 |

## 6. 明确不做的事

- 不发明新语法、不替代 SQL——语法层只加语义（三值、确定性、结构化错误）；
- 不做分布式/NewSQL；
- 不把「GPU 支持」写进路线图（没有硬件就不承诺）；
- 不为 q 做完整的解释器（动词/副词按需增量）。

## 7. 验收约定

每个切片必须给出：

1. 独立 oracle：真值表逐项、暴力实现或第二实现；
2. 性质测试：往返、结合律/交换律、越界报错；
3. 性能预算：打包/向量运算的每 trit 成本不高于 `r3` 基线；
4. 负结果入册：不支持的组合（跨域、溢出）必须显式报错，不静默降级。

## 8. 对模型的利好：语言层、语义层、表示层

上面的分析只回答了「智能体怎么少踩坑」。再往下一层问：这套东西对**模型本身**
（预训练、推理、微调、多智能体）有什么结构性利好？答案分三层，每层都对应 trit-db
里已经存在或已落地的东西。

### 8.1 三层接口

| 层 | 方向 | 模型侧 | trit-db 侧 | 状态 |
|---|---|---|---|---|
| 语言层 | 模型 → 数据库 | 生成查询、读错误、重试 | 结构化错误（PostgreSQL SQLSTATE + hint）、`certainty()` 答案等级 | M9 已落地（两项都完成） |
| 语义层 | 数据库 → 模型 | 置信度 / 冲突 / 缺失 / 计数 | Ł 注解（千分位）、Belnap `BOTH`、K3 `UNKNOWN`、ℕ 计数 | 已存在（`LOGIC` 列 + `ann`） |
| 表示层 | 模型 ↔ 数据库 | 三值权重、嵌入、投票 | `r3` 打包（1.6 bit/weight）、平衡三进制、`tritvec` 动词 | M8 已落地 |

### 8.2 六条具体利好

1. **工具调用收敛**：错误可判定（93% 的 TypeQL 错误是信号）→ 重试轮数下降。
   模型不需要「猜哪里错了」，错误里带列名、函数名、合法值域。
2. **校准（说「不知道」）**：`CERTAIN / CONTINGENT / IMPOSSIBLE` 给模型一个可引用的
   不确定等级，而不是把 `NULL` 当「不知道」；幻觉的很大一部分来自「无法表达不知道」。
3. **可解释的记忆 / RAG**：内容寻址（CAS）+ 三值图可达性（`certain/contingent/impossible`
   带见证路径）+ Belnap 冲突检测，比余弦相似度更容易审计「为什么召回这条、为什么冲突」。
4. **可验证奖励**：确定性等级由语义产生（模型枚举 / 修复枚举），不是模型自报，
   可以直接作为 RL 的可验证奖励结构（verifiable reward）。
5. **推理带宽**：三值量化（BitNet 1.58-bit）与 `r3` 打包同构——1.6 bit/weight，
   对 `f32` 是 20×、对 `f16` 是 10× 的带宽压缩，而 LLM 推理的瓶颈正是带宽。
   `TernaryVec::quantize/dequantize` 给出 `alpha/2` 的误差界，`|w| > 1.5·alpha` 时
   饱和到 `±1`（显式记录的代价，不静默）。
6. **多智能体共识**：`+1 / 0 / -1` 是反对/弃权/赞成的最小表示，`TernaryVec::tally`
   用平衡三进制求和，天然无偏（没有「缺省算反对」的偏差）。

### 8.3 风险与约束

- **不能把错误信号做成奖励 hack**：等级必须来自可验证的语义（模型枚举、修复枚举、
  类型检查），不能由模型自报；否则模型会学会「制造可重试的错误」。
- **量化误差必须有界且公开**：`alpha/2` 只在 `|w| ≤ 1.5·alpha` 内成立，越界饱和要写进
  文档和错误信息，而不是悄悄截断。
- **不为「对模型友好」跳过类型检查**：严格类型是错误信号的前提；放宽检查等于把
  静默错误请回来。

### 8.4 M8/M9 已落地的接口

- `certainty(expr [, threshold])`（SQL）：把注解列投影为 `CERTAIN` / `CONTINGENT` /
  `IMPOSSIBLE`，与 `UNDER REPAIR` 共用 `Certainty` 枚举；Ł 阈值按千分位、ℕ 按计数，
  越界与非注解值显式报错。详见 `docs/results/M9-CERTAINTY.md`。
- 结构化错误：`SqlError::code()` 返回 PostgreSQL SQLSTATE（`42P01` / `42703` / `42803` / `23502`
  / `23505` / `22012` …），`hint()` 给出可执行的修复建议；CLI 输出
  `... [SQLSTATE 42P01]` + `hint: ...`，pgwire 的 `ErrorResponse` 带 `C`（SQLSTATE）与
  `H`（hint）字段。模型可以按码分支、按 hint 改查询，不必解析散文。
  列/表名拼错时还会用 Levenshtein 给出 `did you mean `status`?` 候选
  （`UnknownName { kind, name, candidates }`），模型可以直接改拼写。
  端到端闭环（6 个典型错误按 hint 一次修正成功）见 `docs/results/M9-AGENT-RETRY.md`。
  详见 `docs/results/M9-STRUCTURED-ERRORS.md`。

- `TernaryVec::quantize(weights, alpha)` / `dequantize(alpha)`：BitNet 风格三值量化，
  半跨度误差界 + 饱和语义；
- `TernaryVec::tally()`：`+1/0/-1` 投票的平衡三进制计票；
- `confidence_to_annotation(confidence)`：模型置信度 `[0,1]` → Ł 注解千分位，
  越界 clamp、`NaN` 报错——这是「模型输出直接进 `LOGIC LUKASIEWICZ` 列」的适配层。
